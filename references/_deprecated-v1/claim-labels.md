# M5 · 声明标签与置信度

> 标签体系：verify-gate（svy04/ballast）
> 反例解释：Cleanlab TLM
> 忠实不确定性：ICML 2026（arXiv 2605.01428）

---

## 五标签

| 标签 | 含义 | 升级条件 | 使用限制 |
|---|---|---|---|
| **`confirmed`** | 已过闸 | ① 先主动找过反证 ② ≥2 个**独立一手源** ③ 已记录检索过程 | 可当事实陈述 |
| **`observed`** | 你或工具直接看到 | 单次直接观测 | 必须带"观测于 <时间>"；**n=1 是轶事，不是结论** |
| **`assumed`** | 推断，合理但未验证 | — | **文中必须带标签**，不许裸奔 |
| **`hearsay`** | 某来源说的，未见一手 | — | 必须点名来源 |
| **`unknown`** | 无依据 | — | 说"未知"，**绝不填空** |

### 关键规则

- **未贴标签的声明，不得以事实口吻呈现**——在对话里、文档里、代码注释里，任何地方都不行。
- **博客引博客 = 一个源，不是两个。** 独立一手源要求信源之间没有转述关系。
- **已声明样本量。** n=1 只能 `observed`。
- **已声明边界。** 这条在哪不成立？适用范围必须写。
- **打日期戳。** 超过 90 天的已验证知识，重新验证后才能依赖。
- **记录留存。** 核查结果要写在声明所在的地方。`confirmed` 标签却无记录可查 = 假徽章。

## 置信度分级与话术

**忠实不确定性**：语言层面的确信度必须对齐内部确信度。内心摇摆时措辞留余地，内心笃定时才用确定语气。

| 级别 | 内在状态 | 该这么说 |
|---|---|---|
| **高** 0.85–1.0 | 有源、找过反证、多源一致 | "根据 X 文档 §2.1，……" |
| **中** 0.6–0.85 | 有源但单一，或有轻微不一致 | "目前只有 X 一个来源提到……，建议交叉核实" |
| **低** 0.3–0.6 | 推断，无直接证据 | "据我所知倾向于……，这一条我没把握，需要核实" |
| **无** 0–0.3 | 无依据 | "这个我不确定" / "资料里没提" / "需要查证" |

**禁止**：用斩钉截铁的语气说没把握的事。这是幻觉最典型的表现形式——不是内容错，是**语气骗人**。

## 反例解释（必填项）

每条非 `confirmed` 的声明，必须附：

```
"alternative": "另一个合理答案是 X"
"counter_evidence_direction": "反证方向：查 Y 是否成立"
```

> Cleanlab TLM 的做法：给 0.03 分，不如说"我发现了另一个合理答案：December"。
> **给反例比给分数有用得多**——它把"我不确定"变成了"你可以去查这里"。

## 为什么「拒答」不是解法

ICML 2026 论文的测算：

| 判别力 (AUROC) | 把错误率从 25% 压到 5%，需丢弃的正确回答 |
|---|---|
| 0.71（当前典型水平） | **52%** |
| 0.85（接近文献天花板） | **28%** |
| 0.95（需达到才可忽略） | 目前无方法接近 |

**结论**：纯靠"不确定就闭嘴"代价高到不可用（"实用性税"）。正确做法是**说，但带上校准过的置信度**——保留有用信息，同时把错误信息的危害降到最低。

## 判定示例

```
声明："该项目使用 Rust 编写"

✅ confirmed
   反证已查（搜过"X 项目 语言"反面说法）
   源：官方 README §Tech Stack + GitHub Languages 页（两个独立一手源）
   样本量：n/a（静态事实）
   边界：指主仓库，不含 examples/ 下的 Python 脚本
   日期：2026-09-16

⚠️ observed
   `ls src/` 看到大量 .rs 文件
   → 只能说"观测于 2026-09-16，src/ 下主要为 .rs 文件"
   → 不能说"该项目使用 Rust 编写"（可能混有其他语言，未穷尽）

❌ 反例：直接说"该项目使用 Rust 编写"而不标任何东西
   → 这是幻觉的高发形态：结论正确但越权
```
