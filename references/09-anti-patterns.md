# 09 · 反模式与交付前自检

---

## 反模式（明确禁止的"假核查"）

| ❌ 别这样 | 为什么不行 | 该怎么做 |
|---|---|---|
| 在同一段上下文里"再检查一遍" | 没隔离 = 被自己的草稿锚定。CoVe 论文证明 factored 明显优于 joint | 开独立子任务/子 agent，禁止带入初稿 |
| 让模型自报"已验证"就算数 | 自报状态不是证据 | 要可追溯的源或工具输出 |
| 靠调 temperature 治幻觉 | 实证研究（npj Digital Medicine）：影响很小 | 靠结构和流程，不靠参数 |
| 无限加长 prompt | 长 prompt 反而使错误 **+10%** | 拆短、拆步骤 |
| 迷信 CoT / 长推理 | 复杂任务上 CoT 可能使幻觉 **+12%**；推理模型长文本摘要幻觉率 >10%（Vectara 榜单） | 推理必须配验证，不能替代验证 |
| 检索到什么就用什么 | RAG 静默失败 → "有据可查的假货"，隐蔽性最强 | 过滤噪声 + 强制引用追踪 + 相关性阈值 |
| 只报准确率 | 单一指标掩盖弃权代价 | 同时看错误率 + 弃权率 |
| 把"我不知道"当失败 | 当前评测惩罚弃权，导致模型习惯硬猜 | 本地反向激励：弃权是正确行为 |
| 用完即弃的核查 | 下次照样犯 | 每个出错案例进回归集 |
| 用户夸你就当验证 | 那是感官数据 | 设计可判定的检查 |
| 大项目里凭记忆陈述现状 | 记忆会漂移，且漂移不可自察 | 先读文件/跑命令 |
| 采信子 agent 的自述 | 它的报告也是声明 | 执行同闸独立验证 |
| 用二手数字当事实 | 口径不一致，会级联放大 | 回溯一手，查不到标 `unknown` |
| 高置信度 = 高正确率 | 判别力 AUROC 仅 0.70–0.85，模型指不出哪条错 | 置信度只用于路由，不用于免责 |
| **对小改动也启动全套核查** | 无可判定事实时核查收益为 0，纯属拖慢速度 + 烧 token；小任务上还会挤掉本该用于正事的预算 | 先过 SKILL.md「入场门」四问，全「是」就走浅模式直接答 |
| **心算数值后直接写进正文** | 计算是确定性任务。心算没有执行记录，无法复核也无法定位错在哪一步 | 一律交给 Python/SymPy 实跑，数值结论附执行记录（见 `references/18-math-mode.md`） |
| **把"代码跑通了"当"算对了"** | 工具**成功** ≠ 通过：语法对、量纲对、但变量代错的代码会静默跑通，产出带"已验证"外衣的错答案 | 加第二层：逐项问「这个变量指题面里的哪个词」，指不出来即未接地、降级 |
| **给病态题假设一个数填进去** | 任意条件编造。得到一个唯一但无意义的答案，比说"信息不足"糟得多 | 先追问缺哪个前提；不可追问则条件化；非假设不可须显著标注 + 给敏感性 |
| **用"再仔细检查一遍"当数学闸门** | 该层能力不随模型变强、也不随 thinking mode 提升；未经训练的模型上 thinking 反而降低主动批判性思考 | 用结构化前置三问（条件够否/矛盾否/定义域成立否），不用泛泛的"认真点" |
| **核对答案时先看候选答案** | 锚定效应：先看候选会把假阳性从 0.012 推回 0.719，整条验证链归零 | 裁判**先自立作答**再看候选（即铁律 2 的数学形态） |

## 交付前自检表

输出前逐条过。**有任何一条不过，不许交付。**（也可交给 `scripts/claim_lint.py` 自动检查其中可判定的部分）

### 事实层

- [ ] 每条事实性声明都有来源？无源的已删除并留 `[]`？
- [ ] URL / DOI / 论文 / 实体 / API / 文件路径 / 版本号——**逐个真查过**（hardcheck.py）？
- [ ] 数字（百分比、日期、金额、版本号）回溯到一手来源了？
- [ ] 二手来源的数字，有没有标 `hearsay` 并点名出处？
- [ ] 有没有把"我记得"当成事实写？

### 验证层

- [ ] 核查是在**独立子任务**里做的，没被初稿锚定？
- [ ] 升级 `confirmed` 前**主动找过反证**？
- [ ] `confirmed` 的声明有 **≥2 个独立一手源**？（博客引博客 = 1 个）
- [ ] 工具失败 / 检索为空的，记成 `unverified` 而不是默认通过？
- [ ] 低置信声明附了**反例解释**？

### 表达层

- [ ] 语气对齐置信度？有没有用确定语气说没把握的事？
- [ ] `assumed` / `hearsay` 的标签在正文里可见？
- [ ] 声明了样本量？（n=1 只能 `observed`）
- [ ] 声明了边界？（这条在哪不成立）
- [ ] 打了日期戳？老知识（>90 天）重验过？

### 执行层

- [ ] "已完成"的每一条都有可追溯证据？
- [ ] 贴的是**完整命令输出**，不是"应该过了"？
- [ ] 子 agent 的报告独立验证过，没有采信它的自述？

### 大项目层（v2）

- [ ] 关于代码库现状的陈述，本次会话实际读过文件/跑过命令？
- [ ] 关于项目约定的陈述，对照过 `ledger.json`？
- [ ] 账本跑过 `check --drift`，无 `stale` 条目被当事实引用？
- [ ] 完成标准里的机器可验证项都实际跑过？

### 风险层

- [ ] **先过了入场门四问吗？小任务有没有被误套全套核查？**

### 数学层（出现数值或符号结论时）

- [ ] **每个数字都有执行记录吗**？（或明确标注为假设/估计）
- [ ] **变量接地自问过吗**？「这个 X 指题面里的哪个词」能指出来吗？
- [ ] **口径一致吗**？（分母、含税、时间区间、单位）
- [ ] **条件齐不齐判过吗**？（缺就追问，没有假设填空）
- [ ] **定义域成立吗**？（开根号负数、除零、对数非正）
- [ ] **核对时裁判先自立作答了吗**？（顺序没反）
- [ ] 有没有把"工具跑通了"当成"算对了"？
- [ ] **精度与舍入声明了吗**？（有效数字 / 误差界）
- [ ] 风险等级判对了吗（L0/L1/L2）？
- [ ] L2 场景强制检索 + 人工闸门走了吗？
- [ ] 需要人工复核的标了 `needs_human_review`？

## 快速退出条件（出现任一情况，停止作答并交给人）

1. 关键事实**检索不到**且无法判定 → 说"未找到可靠来源"，不要猜
2. 多个独立源**互相矛盾** → 呈现矛盾，不要选一个假装没有分歧
3. 涉及不可逆操作（删库、发布、外发、付款）且未获明确授权 → 停下来问
4. L2 场景且置信度 < 0.6 → 标 `needs_human_review`
5. 用户要求"就凭你知道的答"且这是高风险问题 → 全局降级为 `assumed` 并明确标注
