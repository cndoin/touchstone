# 19 · 生物医学模式：基因、ID 与统计口径不许编

> **一句话：生信里"能被数据库判定"的东西不许猜，而"结论能推到哪"必须显式画线。**
>
> 生信幻觉跟一般事实幻觉有个结构性区别——它的**大部分是格式可判定的**：
> 物种-基因命名有规范、ID 有前缀、统计量有定义、注释库与物种一一对应。
> 也就是说，这一类里很大一部分能做成脚本闸门，做到接近零。
> 剩下那部分（结论外推到哪算越界）才是真难点，本章给措辞闸门。

---

## 0. 什么时候进生物医学模式

触发条件（满足任一条即进入）：

- 输出涉及**基因 / 蛋白 / 变异 / 通路 / 细胞类型**等生物实体
- 涉及**组学数据分析**（转录组、单细胞、空间、甲基化、微生物组、GWAS、MR）
- 涉及**统计结论**（差异表达、富集、生存分析、相关性、因果推断）
- 涉及**临床解读**（诊断、预后、用药、风险）
- 你正打算把"通常细胞数在几千量级""这类基因一般高表达"写进正文

不触发：纯概念解释、软件安装教学、术语词典式问答、与生物实体无关的代码重构。

**入场门优先。** 生物医学模式是本套件的**内部档位**，不是绕开入场门的后门。
但要注意：SKILL.md 的风险分级里，**医疗属于 L2**（高风险不可逆），
所以本模式的实际起点比数学模式更靠前——**涉及临床解读的一律按 L2 处理**。

## 1. 生信幻觉长什么样：七个层，三种治法

生信幻觉不是一个问题。层与层之间治法不通用，**用错层等于没治**。

| 层 | 症状 | 本质 | 可判定性 | 治法 | 谁来做 |
|---|---|---|---|---|---|
| **① API / 函数层** | `enrichGO2()`、`RunWNN()`、`dotplot(split=)` | 函数名参数名不存在 | **100%** | 对 NAMESPACE 白名单做静态校验 | **已有**：`cp_lint.py` / `sc_lint.py` |
| **② 生物实体层** | 编造基因符号；人鼠基因大小写混用 | 命名规范被无视 | 高（格式可判） | 物种锁 + 命名规范校验 | `bio_guard.py --only species,gene` |
| **③ 标识符层** | SYMBOL/ENSEMBL/ENTREZID 混用；OrgDb 与物种不配 | ID 体系边界被抹掉 | 高（前缀可判） | ID 体系识别 + 配对表 | `bio_guard.py --only id,orgdb` |
| **④ 注释术语层** | KEGG 用学名、WikiPathways 用代码；通路 ID 与名对不上 | 两套命名体系混用 | 中-高 | 体系配对校验 | `bio_guard.py --only orgdb` |
| **⑤ 统计口径层** | `p` 当 `padj`；logFC 不说底数；检验前提不满足 | 统计量定义被省略 | 中 | 口径三连检查 | `bio_guard.py --only stat` |
| **⑥ 数值层** | 编造 p 值 / FC / 细胞数；复述时改数 | 数字没执行记录 | 高（有记录即判） | **数值必须有执行记录**（同 18-math-mode） | 执行日志 + `bio_guard.py --only numeric` |
| **⑦ 结论边界层** | 相关当因果；体外→临床；小鼠→人；单数据集→普适 | 适用范围没画线 | **低**（需人判） | 外推三闸 + 措辞模板 | `bio_guard.py --only overclaim` + 人判 |

**用错层的代价**：
- 给第 ⑦ 层堆脚本不管用——"这个结论能不能推广"机器判不了，**只能靠强制写限定语句**；
- 给第 ② 层讲道理不管用——"注意大小写"写一百遍也没用，**要机器查**；
- 第 ① 层**已经有专门工具**，别在本章重造（见第 6 节分工表）。

## 2. 第一类：实体的真伪（可判定，机器查）

### 2.1 物种锁（先锁物种，再谈基因）

**任何基因符号出场之前，物种必须已经确定。** 这不是礼貌问题——同一个符号在不同物种里指不同基因。
物种只能来自：用户输入、数据文件元信息、`search_kegg_organism()` 实际探测。
**不许从"看起来像"推断。**

| 物种 | 常用代号 | 参考基因组 | 注释库 |
|---|---|---|---|
| 人 *Homo sapiens* | `hsa` | GRCh38 / hg38 | `org.Hs.eg.db` |
| 小鼠 *Mus musculus* | `mmu` | GRCm39 / mm39 | `org.Mm.eg.db` |
| 大鼠 *Rattus norvegicus* | `rno` | mRatBN7.2 / rn7 | `org.Rn.eg.db` |
| 斑马鱼 *Danio rerio* | `dre` | GRCz11 / danRer11 | `org.Dr.eg.db` |
| 果蝇 *Drosophila melanogaster* | `dme` | BDGP6 / dm6 | `org.Dm.eg.db` |
| 线虫 *Caenorhabditis elegans* | `cel` | WBcel235 | `org.Ce.eg.db` |

⚠️ **这张表是配对关系，不是清单。** 左边三列必须一致；`organism="mmu"` 配 `org.Hs.eg.db` 是硬幻觉。

### 2.2 基因命名规范（各物种规则不同，这是最高频的实体幻觉）

| 物种 | 规范 | 正确 | 典型错误写法 |
|---|---|---|---|
| 人 | 全大写 | `TP53` `BRCA1` `MT-ND1` | `Tp53` `brca1` `mt-nd1` |
| 小鼠 | 首字母大写，其余小写 | `Trp53` `Brca1` `mt-Nd1` | `TP53` `BRCA1` `MT-ND1` |
| 大鼠 | 首字母大写，其余小写 | `Tp53` | `TP53` |
| 斑马鱼 | 全小写 | `tp53` | `TP53` |
| 果蝇 | 首字母小写（蛋白首字母大写） | `p53` | `P53` |
| 线虫 | 全小写斜体（蛋白全大写） | `ced-3` | `CED-3` |

规范来源：HGNC（人）、MGI（小鼠）、RGD（大鼠）、ZFIN（斑马鱼）、FlyBase（果蝇）、WormBase（线虫）
各自的命名指南。**这些是机构规范，不是"惯例"——按错就是错。**

**线粒体基因是最容易露馅的地方**：人的是 `MT-ND1`（大写前缀），小鼠的是 `mt-Nd1`（小写前缀）。
一篇文章里同时出现 `MT-` 和 `mt-` 前缀且没说明物种切换 ⟹ 编造信号。

**跨物种同源叙述是允许的，但必须显式**：
> ✅ "小鼠 *Trp53*（人类同源基因 *TP53*）敲除后……"
> ❌ "*TP53* 在小鼠模型中敲除后……"（物种与命名不符）

### 2.3 ID 体系：一次分析里只能有一套主干 ID

生信 ID 有十几个体系，**前缀是可判定的**，混用即幻觉信号：

| 体系 | 形态 | 例子 | 谁在用 |
|---|---|---|---|
| HGNC Symbol | 字母（+数字/-） | `TP53` | 人基因 |
| Entrez Gene ID | 纯数字 | `7157` | NCBI |
| Ensembl Gene | `ENS` + 物种码 + 11 位 | `ENSG00000141510` | Ensembl |
| Ensembl Transcript | `ENS` + 物种码 + `T` + 11 位 | `ENST00000269305` | Ensembl |
| RefSeq mRNA | `NM_` / `XM_` | `NM_000546` | NCBI |
| RefSeq Protein | `NP_` / `XP_` | `NP_000537` | NCBI |
| GO term | `GO:` + 7 位 | `GO:0006915` | Gene Ontology |
| KEGG Pathway | 物种码 + 5 位 | `hsa04115` | KEGG |
| KEGG Orthology | `K` + 5 位 | `K04451` | KEGG |
| Reactome | `R-` + 物种 + 数字 | `R-HSA-109582` | Reactome |
| WikiPathways | `WP` + 数字 | `WP254` | WikiPathways |
| miRBase | 物种码 + `miR`/`let` | `hsa-miR-21-5p` | miRBase |
| UniProt | 6-10 位字母数字 | `P04637` | UniProt |

**硬规则：**

1. **Ensembl 物种码必须与物种一致**：人 `ENSG`、鼠 `ENSMUSG`、大鼠 `ENSRNOG`、斑马鱼 `ENSDARG`、
   果蝇 `FBgn`（不是 ENS 前缀）、线虫 `WBGene`。
   出现 `ENSMUSG` 但文中说"人类样本"⟹ **硬幻觉**。
2. **`keyType=` 必须与实际 ID 形态一致**。传 `ENSEMBL` 进去却说 `keyType="ENTREZID"` ⟹ 结果全空，
   但**脚本不报错**（这是最阴的一种：静默失败，返回空结果集）。
3. **转换必须留痕**：`bitr()` / `bitr_kegg()` / `mapIds()` 的输入输出要对得上，
   转换后基因数**减少**是正常的（有些基因映射不上），**变多**一定是错的。
4. **UniProt 与 RefSeq Protein 不可互换写法**：`P04637`（UniProt）≠ `NP_000537`（RefSeq）。

### 2.4 注释库 / 通路库的命名体系（两套体系，别混）

| 函数 | `organism=` 接受 | 例子 | 常见错误 |
|---|---|---|---|
| `enrichKEGG` / `gseKEGG` / `enrichMKEGG` | **三字母 KEGG 代码** | `"hsa"` `"mmu"` `"dre"` | ❌ `"Homo sapiens"`（会当 UNKNOWN，结果全空） |
| `enrichWP` / `gseWP` | **拉丁学名** | `"Homo sapiens"` `"Mus musculus"` | ❌ `"hsa"` |
| `enrichGO` / `gseGO` | 不给 organism，给 `OrgDb` | `org.Hs.eg.db` | ❌ 给物种字符串 |
| `enrichPathway`（Reactome） | `organism="human"` 或 `"mouse"` 等**小写英文名** | `"human"` | ❌ `"hsa"` / `"Homo sapiens"` |
| `msigdbr` | `species="Homo sapiens"`（学名） | `"Homo sapiens"` | ❌ `"hsa"` |

**这三套（代码 / 学名 / 库名）互相之间不能换用**，换用后多数情况**不报错**，
而是静默返回空结果或 UNKNOWN——比报错危险得多。

### 2.5 文献标识（生信论文引用重灾区）

- **PMID**：6–9 位纯数字。`PMID: 12345678`
- **DOI**：`10.` + 4–9 位注册号 + `/` + 后缀。`10.1038/s41586-024-07500-0`
- **期刊名缩写**：NLM 标准缩写，不是自己截的（`Nat Genet` 不是 `Nat. Gen.`）

**这些一律走 `hardcheck.py`，不许凭印象写。** 格式合法 ≠ 存在：

```bash
python3 scripts/hardcheck.py --doi 10.1038/s41586-024-07500-0
python3 scripts/hardcheck.py --batch refs.json      # PMID 走 urllib 解析
```

## 3. 第二类：数字的真伪（可判定）

### 3.1 口径三连（生信报告不写全这三样 = 没验证过）

| # | 口径 | 必须写清 | 不写会怎样 |
|---|---|---|---|
| 1 | **显著性口径** | 报的是 raw `p` 还是校正后 `padj` / `q` / `FDR`？校正方法是什么（BH / Bonferroni / BY）？ | `p<0.05` 与 `padj<0.05` 在 2 万基因里差好几个数量级 |
| 2 | **效应量口径** | `logFC` 的**底数**（log2 / ln / log10）；是原始还是标准化后 | 同一数据 `logFC=1` 是 2 倍还是 e 倍，差 44% |
| 3 | **单位与基数** | 细胞数 / 读数 / 样本量；分母是谁（总细胞？有效细胞？） | 分母换了结论就变 |

**硬条款：报了一个差异基因的 p 值，必须同时能说出这三样。** 说不出来 ⟹ 降级为 `assumed`。

**检验方法与数据类型的匹配**（前置闸门，答之前判）：

| 数据类型 | 该用什么 | 不该用什么 |
|---|---|---|
| Bulk RNA-seq counts | DESeq2 / edgeR（**负二项**） | ❌ t 检验 / limma（未 voom） |
| 单细胞 marker | Wilcoxon（Seurat 默认）/ MAST | ❌ 直接把细胞当独立样本做 t 检验（**伪重复**） |
| 多组比较 | ANOVA + 事后检验 | ❌ 两两 t 检验不校正 |
| 生存数据 | log-rank / Cox | ❌ 卡方 |
| 比例 / 组成数据 | CLR / 专门方法 | ❌ 直接对比例做 Pearson |

**伪重复（pseudo-replication）是生信里最隐蔽的统计幻觉**：
把同一个体的 5000 个细胞当成 5000 个独立样本来算 p 值，
自由度虚高几千倍，p 值小到荒谬。**单细胞差异分析的正确统计单元是个体/样本，不是细胞。**

### 3.2 数值执行记录（bio 版，直接继承 18-math-mode 第 2 节）

**生信数值结论必须来自被实际读取的执行输出，不许来自"典型值"。**

| 场景 | 必须来自 | 禁止 |
|---|---|---|
| p 值 / padj | `results.csv` 或 `FindMarkers` 输出文件 | "一般 p 都很小" |
| logFC | 同上 | "上调约 2 倍左右" |
| 细胞数 / 聚类数 | `table(Idents(obj))` 输出 | "大约 10 个 cluster" |
| GSEA NES / 富集分数 | `gseaResult` 对象的实际列 | "NES 通常在 2 以上" |
| 生存 HR / 中位生存 | `coxph` / `survfit` 输出 | 凭印象 |

**"数据集里常见的值"不是证据。** 报告里的每个数字，都要能追到某个具体输出文件的具体列。
没有这段记录 ⟹ 该数字标 `unknown`，**不许写进结论**。

⚠️ **别把"代码跑通了"当成"数对了"。** 脚本成功执行只证明语法对——
变量代错（把 `padj` 列读成了 `pvalue` 列）照样静默跑通，产出一个带执行记录的错数字。
第二层必须问：**「这个数字，是从哪一列的哪一行读出来的？」** 指不出来 ⟹ 未接地。

### 3.3 可复现性（没有 seed 的结果不是结果）

用到随机过程的步骤**必须固定种子**，否则数字无法复现：

| 工具 | 参数 |
|---|---|
| `RunUMAP` | `seed.use=42` |
| `FindClusters` | `random.seed=0` |
| `SCTransform` | `seed.use=1448145` |
| `RunTSNE` | `seed.use` |
| `SketchData` | `seed=123` |
| `gseGO` / `gseKEGG` | `seed=TRUE`（fgsea permutation） |
| 任何 bootstrap / 交叉验证 | 显式 seed |

**软件版本也要记录**：DESeq2 1.38 与 1.42 的默认行为可能不同；
Seurat v4 与 v5 的图层模型不同（`slot=` 与 `layer=`）。**"在我的机器上跑出来的"不是结论，是观测。**

## 4. 第三类：结论的边界（半可判定，措辞闸门 + 人判）

这一层机器判不了对错，但**可以判"有没有画线"**。没画线的结论 = 幻觉风险敞口。

### 4.1 外推三闸（跨越任一，必须显式标注为假设）

| 闸 | 从 → 到 | 必须写的话 |
|---|---|---|
| **闸 1 · 体外 → 体内** | 细胞系 / 类器官 → 患者 | "该结论目前仅在 *in vitro* 水平成立，体内有效性未验证" |
| **闸 2 · 动物 → 人** | 小鼠 / 斑马鱼 → 人类 | "系跨物种外推，人类适用性需独立验证" |
| **闸 3 · 相关 → 因果** | 表达相关 / 共表达 → 因果驱动 | "为观察性关联，不能排除混杂；因果需 MR / 干预实验" |

**MR（孟德尔随机化）也不是万能因果**——它有三条硬假设（相关性、独立性、排他性），
报告时**必须说明这三条是否被检验过**（尤其排他性，多数情况无法完全验证）。
把 MR 结果直接说成"证明因果"是 L2 级别的过度解读。

### 4.2 结论必须带适用范围（模板）

每条主要结论后面，**必须**能填完这个句式：

```
本结论基于：<数据集/队列> · <物种> · <组织/细胞类型> · <样本量> · <方法>
适用边界：<不适用于什么>
```

填不满 ⟹ 结论降级为 `assumed`。

### 4.3 过度解读的典型句式（见到就改）

| ❌ 越界表述 | 为什么错 | ✅ 改成 |
|---|---|---|
| "证明了 X 导致 Y" | 观察性数据推不出因果 | "观察到 X 与 Y 的关联，因果方向未确定" |
| "可直接用于临床诊断" | 生信标记物需前瞻性队列验证 | "在 <队列> 中显示区分能力，尚需独立队列验证" |
| "小鼠结果适用于人类" | 跨物种外推 | "小鼠模型中的结果提示……人类相关性需验证" |
| "该通路是治疗靶点" | 靶点需功能验证 | "该通路为潜在干预方向，需功能实验验证" |
| "所有患者均应……" | 无人群限定 | "在 <明确人群特征> 的患者亚组中……" |
| "无可否认 / 毫无疑问 / 必然" | 绝对化 | 删除，或改为带置信度的表述 |
| "首次发现" | 需要查新 | 查不到就说"未检索到相关报道"（而不是"首次"） |

**注意：这些不是"禁用词"，是"必须带限定"的词。**
"证明"在描述自己的实验设计时（如"Western blot 证明蛋白表达下降"）是合法的；
越界的是**用它连接一个数据支撑不了的结论**。判据是：**这个结论，分析数据本身能不能兜住？**

## 5. 可执行闸门：`bio_guard.py`

```bash
PY=python3          # Windows 用 python

# 检查分析报告（自动识别 report 模式）
python3 scripts/bio_guard.py --file report.md

# 检查 R 脚本（自动识别 script 模式，额外查 seed / organism / keyType）
python3 scripts/bio_guard.py --file analysis.R

# 扫描整个项目目录（教学 / 规范文档必须排除，理由见下）
python3 scripts/bio_guard.py --root . --exclude 'references/*' --json

# 只跑指定检查器
python3 scripts/bio_guard.py --file report.md --only species,id,stat,overclaim

# 离线 + 严格模式（非 pass 一律视为不过）
python3 scripts/bio_guard.py --root . --offline --strict
```

**八个检查器：**

| 检查器 | 抓什么 | 需联网 |
|---|---|---|
| `species` | 物种-基因命名一致性；`MT-`/`mt-` 混用；未锁定物种 | 否 |
| `gene` | 占位符基因名（`GENE1`/`ProteinA`）；脚本全角标点；UniProt 式下划线名 | 否 |
| `id` | ID 体系识别与混用；Ensembl / KEGG / Reactome 前缀与物种冲突 | 否 |
| `orgdb` | `organism=` 与注释库、物种的配对；代码 vs 学名混用 | 否 |
| `stat` | 显著性口径 / 效应量底数 / 校正方法；伪重复；随机种子缺失 | 否 |
| `numeric` | 数值声明清单（供逐条接地核对） | 否 |
| `overclaim` | 外推三闸越界表述 | 否 |
| `citation` | PMID / DOI **格式**校验（存在性走 `hardcheck.py`） | 否 |

**退出码：0=全部通过 1=存在失败 2=存在需人工确认项 3=用法错误**
（与套件其它脚本一致；`--strict` 下，需人工确认项也按失败计。）

**适用范围（重要）**：它面向**待交付的分析产物**（分析报告、R/Python 脚本、结果摘要），
**不是**用来扫教学 / 规范文档的 —— 后者成篇都是故意写错的示例（本章自己就是），
扫出来只会是一屏假红，把真问题一起淹掉。要扫目录时用 `--exclude` 把这类目录排掉：

```bash
python3 scripts/bio_guard.py --root . --exclude 'references/*' --exclude 'docs/*'
```

**它不管什么**（别指望它）：基因是否**真实存在**（要查数据库）、通路 ID 与名称是否**对应**、
数值是否**算对**、结论是否**科学**。它只保证"**格式与口径层面没有幻觉**"——
这一层能机器化，就机器化到零；剩下的一层明确交给人和检索。

## 6. 与既有生信技能的分工（重要：不要重复造）

本机已有三套生信技能，它们**各自有事实底座和 lint**，本章**不重复它们的工作**：

| 技能 | 覆盖 | 它的闸门 | 本章补什么 |
|---|---|---|---|
| `clusterprofiler-skill` | 38 个 YuLab R 包（富集 / 通路 / 可视化 / 树 / 微生物组） | `tools/cp_lint.py`（函数名、参数名、拼写、全角符号） | 第 ②③④⑤⑥⑦ 层 |
| `seurat-sc` | Seurat v5 单细胞与空间转录组 | `tools/sc_lint.py`（含 v5 layers、deprecated 参数） | 同上 |
| `mr-agent` | 孟德尔随机化 / GWAS / SMR | `preflight.py` + 110 条 selftest | 第 ②③⑥⑦ 层（尤其 MR 因果表述） |
| **touchstone（本章）** | **跨技能的共同幻觉面** | **`bio_guard.py`** | **实体 / ID / 口径 / 结论边界** |

**正确的调用顺序**（三层闸门都要过，顺序不能反）：

```
[1] 技能层  → cp_lint.py / sc_lint.py      （函数名参数名对不对）
[2] 通用层  → hardcheck.py                  （PMID / DOI / 路径 / 版本是否存在）
[3] 领域层  → bio_guard.py                  （物种 / ID / 口径 / 结论边界）  ← 本章
[闸] 交付前 → claim_lint.py                 （输出契约）
```

**第 1 层查不出来第 3 层的问题**：`cp_lint.py` 会让 `enrichKEGG(organism="Homo sapiens")` 通过
（参数名合法、类型合法），但它是**语义错误**——这是 `bio_guard.py --only orgdb` 的活。
反过来，`bio_guard.py` 查不出 `enrichGO2()`。**两层都要跑。**

## 7. 本机环境边界（诚实说明）

本机（Windows）现状：**Python 3.13 有，R 没有**（`which R` 实测无输出），Docker 无，WSL 被拦。

因此：

- **能做的**：写脚本、静态校验、规划流程、解读报错、核查声明与口径、检查文献格式。
- **不能做的**：真实运行 `Rscript` 出图出数 —— 所以**任何 p 值 / 富集分数 / 细胞数都不许编**。
- 需要真跑时给用户三选一，并说清代价：
  1. 本机装 R（≥4.2）+ BiocManager 装包（首次 15–40 分钟）；
  2. 交付脚本到 Linux 服务器 / HPC / Colab；
  3. GitHub Actions（`r-lib/actions/setup-r` + `setup-bioconductor` + `renv` 缓存）。

**没跑就是没跑。** 这一条没有例外，也不接受"我推算出结果应该是……"。
