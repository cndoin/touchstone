# 02 · M1 上下文判定器

> 来源：RefChecker（amazon-science, arXiv 2405.14486, Apache-2.0）的三种上下文设定

**为什么先判这个**：用错核查手段是浪费成本的头号原因。有原文却跑去联网检索 = 引入噪声；没资料却不检索 = 靠参数记忆硬编。

---

## 三种设定

### Accurate Context（准确上下文）

**判据**：存在一份唯一权威的原文，答案应当完全由它导出。

- 单文档摘要 / 抽取
- 合同、法条、规范的条款问答
- 日志、配置文件、代码库的提问
- 用户提供了一段材料并问"里面说了什么"

**手段**：
- ✅ 只对照该文档
- ✅ 长文档（>20k tokens）先**逐字抽取引文**，再基于引文作答（Anthropic 官方做法）
- ❌ 不要跑去联网检索
- ❌ 不要引入外部知识补充

**判定规则**：文档里没有 → 答"文档未提及"，**不许**用自己的知识补。

---

### Noisy Context（噪声上下文）

**判据**：有一堆候选材料，但质量参差、可能不相关、可能互相矛盾。

- RAG 检索结果
- 多文档问答
- 搜索结果汇总

**手段**：
- ✅ 混合检索（稠密 + 稀疏）+ 重排，过滤噪声
- ✅ 给每个 chunk 打相关性/可信度
- ✅ 多来源交叉，保留重合部分，剔除孤证
- ⚠️ **警惕 RAG 静默失败**：检索质量差时，模型会产出"听起来有据可查的假货"——这是隐蔽性最强的幻觉类型
- ⚠️ 检索为空或相关性极低 → **直接终止作答**，说"没检索到可靠材料"，不要强行整合

**判定规则**：只有单一低质量来源支撑的声明 → 最高只能标 `hearsay`，不能 `confirmed`。

---

### Zero Context（零上下文）

**判据**：开放问答，手头没有任何材料，答案只能来自模型参数记忆或外部检索。

**手段**：
- ✅ **必须外部检索**（搜索 / 查官方文档 / 查数据库）
- ✅ 检索不到 → 说"需要核实"或"不确定"
- ❌ **禁止**凭参数记忆下事实性结论
- ⚠️ 长尾事实（人名生日、生僻论文、冷门 API 参数）参数记忆最不可靠，必查

**判定规则**：未检索 = `unknown`。不允许把"我记得好像是……"当成事实输出。

---

## 快速判定流程

```
手头有材料吗？
├─ 没有 → Zero Context → 必须先检索，检索不到就承认不知道
└─ 有
   ├─ 单一权威原文，答案应完全由它导出 → Accurate → 只对照它，不检索
   └─ 多份/检索得到/质量参差 → Noisy → 过滤噪声 + 交叉验证
```

---

## 边界情况（v2 新增，大项目高频）

| 情况 | 处理 |
|---|---|
| **小改动 / 单点问题 / 闲聊创意**（无外部可判定事实、可逆、不对外） | **不进入本套件**——过 SKILL.md「入场门」四问即可，直接答 |
| 有原文，但用户问的是原文之外的事实 | 原文部分走 Accurate，外部部分走 Zero（必须检索） |
| RAG 检索到一份高度权威的完整文档 | 按 Accurate 处理 |
| 用户明确说"别联网，就凭你知道的答" | 转 Zero + **全局降级为 `assumed`**，明确标注未核实 |
| 代码库提问（本仓库结构/内容） | **Accurate**（代码即真相）—— 但必须**实际读文件**，禁止凭记忆 |
| 代码库提问（第三方库行为/API） | 转 **Zero**（查官方文档 / 查本地依赖源码），禁止凭记忆 |
| 项目已做过什么、约定是什么 | 转 **Accurate + 账本**：对照 `ledger.json`；账本与现实冲突 → 以现实为准并更新账本 |
| 跨会话追问（"上次我们定的 X 是什么"） | 必须读账本或 git 历史，**禁止凭印象重建** |
| 子 agent 返回的结论 | 一律视为 `hearsay`，需独立验证后才可升级 |

---

## 判定错误的代价（为什么值得花 30 秒）

| 判错方向 | 后果 |
|---|---|
| Accurate 误判为 Zero | 跑去检索，把外部噪声当成答案，违反忠实性 |
| Zero 误判为 Accurate | 凭记忆硬编，典型知识幻觉 |
| Noisy 误判为 Accurate | 把检索噪声当权威原文，产出"有据可查的假货" |

**判不出来时，默认 Noisy**（最保守、最通用）。
