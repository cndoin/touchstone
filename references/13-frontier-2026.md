## 2. 开源生态（2026 现状）

**共识（多家评测一致）**：没有任何单一工具覆盖全链路。生产栈是分层的：

```
发布前评测(CI)  →  单请求检测器  →  可观测性  →  在线护栏
DeepEval/Ragas     Lynx/HHEM/TLM    Phoenix/Langfuse   Guardrails AI
Promptfoo          DeBERTa-NLI      W&B Weave          NeMo Guardrails
```

| 工具 | 定位 | License（**二手，以仓库 LICENSE 为准**） |
|---|---|---|
| DeepEval | pytest 风格 + Hallucination/Faithfulness/G-Eval，CI 门禁 | Apache-2.0（一说 MIT，**以仓库为准**） |
| RAGAS | RAG 五指标（faithfulness / answer relevancy / context precision / recall / correctness） | Apache-2.0 |
| Promptfoo | YAML + CLI，多模型对比，**红队/对抗测试最强** | MIT |
| TruLens | RAG 三元组 + OpenTelemetry tracing | 开源 |
| Patronus Lynx / Vectara HHEM | 专用 NLI 忠实度模型，比 LLM-judge 便宜得多 | 开源（HF） |
| Guardrails AI / NeMo Guardrails | 在线护栏，可 block / retry / 纠正 | 开源 |
| Arize Phoenix / Langfuse | 可观测 + trace 绑定分数 | 开源 |
| Cleanlab TLM | 不确定性打分 + 反例解释 | 客户端 MIT（需 API key） |

**成本参考（二手）**：每天评估 1 万条 RAG trace（DeepEval + RAGAS）约 $200–600/月；换便宜 judge 模型可降 60–80%。
→ 这正说明**成本路由**不是优化，是必需。

## 3. 与编码安全交叉的新领域：slopsquatting

包幻觉已从"质量缺陷"升级为"供应链攻击面"：模型编造包名 → 攻击者抢注 → 开发者/agent 安装中招。
防护手段与自动核查见 **`14-supply-chain-code.md`**，工具是 `scripts/dep_guard.py`。

## 4. 本套件相对这些成果的定位

训练层（BALTO / Ghostbusters / 元认知训练）我们**改不了模型权重**，不碰。
解码层（DoLa / NTK / logit 类）需要白盒权限，多数商用 API 不给，不依赖。

我们做的是 **Agent 行为层 + 工程闸门层**，正好是开源生态里最空的那一层：

| 层 | 谁在做 | 本套件 |
|---|---|---|
| 训练 / 对齐 | 论文（BALTO 等） | 不碰 |
| 检测算法 | HHEM / Lynx / TLM / LaaB / HalluGuard | **可插拔接入**（插槽在 `06-cost-routing.md`） |
| 评测框架 | DeepEval / RAGAS / Promptfoo | 互补：它们跑 CI 评测，我们管**单次交付的声明闸门** |
| **Agent 行为约束** | 基本空白 | ✅ 强制溯源 / 隔离验证 / 允许弃权 / 风险路由 |
| **可判定项硬核查** | 散落在各处 | ✅ `hardcheck.py` + `dep_guard.py` |
| **大项目账本与漂移** | 基本空白 | ✅ `ledger.py` |
| **宿主强制力（hooks）** | 少量 | ✅ Claude Code hooks（含 8 次上限规避） |
