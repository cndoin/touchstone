# 12 · 不确定性校准操作手册

> 来源：*Nature* 2024 语义熵（Farquhar et al., Oxford）、SelfCheckGPT（arXiv 2303.08896）、ICML 2026（arXiv 2605.01428）
> 定位：当**没有原文可对照、也无法检索**时，怎么判断该不该信自己的答案。

---

## 1. 三类不确定性估计手段

| 手段 | 需要什么 | 可用性 | 本套件的实现 |
|---|---|---|---|
| **Logit 类**（末层概率分布） | 白盒 logprobs 权限 | 多数商用 API 不提供 | 不依赖 |
| **采样类**（多次生成看离散度） | 能多次调用 | 黑盒可用，成本 = N× | `scripts/selfcheck.py` |
| **口头置信度**（模型自报） | 无 | 通用但**普遍过度自信** | 只用于路由，需校准 |

---

## 2. 采样一致性：怎么操作

### 步骤

1. 同一问题**独立采样 3–5 次**（temperature 适当提高以获得多样性；但别指望靠温度治幻觉，它对幻觉率影响很小）
2. 把结果按**语义**聚类——不是按字面，按"意思是否相同"
3. 计算一致度：`最大簇的样本数 / 总样本数`
4. 按一致度路由

### 判定阈值（建议，可按场景调）

| 一致度 | 判读 | 动作 |
|---|---|---|
| ≥ 0.8 | **及格线**（不是确认线） | 仍需 ≥2 独立一手源或硬核查才能升 `confirmed`；否则停在 `observed` |
| 0.6–0.8 | 灰区 | 升级：定向检索 / 子 agent 隔离验证 |
| < 0.6 | 低一致 | **危险信号**。降级为 `assumed`，附反例解释；L2 场景交给人 |

### ⚠️ 天花板（v3.4 修正，必读）

**一手证据**：arXiv 2607.11414（*Confidently Wrong*，2026-07-13）。

> 在 FinQA 上，**8 次采样答案全部一致的那些题里，仍有 15%–23% 是错的**。
> 在这个"自信子集"上，token logprob 与 P(True) 的判别力掉到 **0.55–0.63 AUROC**（接近抛硬币），
> residual-stream 线性探针仍有 **0.68–0.77 AUROC**。

所以原来那句"一致性高只是及格线"不是修辞，是有实测数字的：

- ❌ **禁止**因为 "selfcheck.py 输出 consistency 1.0" 就升 `confirmed`
- ❌ **禁止**把"三次采样都一样"写进证据理由
- ✅ 一致性用于**路由**（决定要不要花钱升级核查），不用于**结论**

> 二手来源对同一子集给出 5%–19% 的错率，与摘要的 15%–23% 冲突。
> **本套件采用摘要数字**，并在对外引用时注明区间有分歧。

### 语义聚类 vs 字面聚类

语义熵（*Nature* 2024）的核心洞见：在**语义层面**而非 token 层面算熵。

- 字面聚类会把"巴黎是法国首都"和"法国的首都是巴黎"判为不同 → 高估不确定性
- 语义聚类把它们判为相同 → 更准确

`selfcheck.py` 提供的是**近似实现**（归一化后的字面相似度 + 可选人工分组）。真正的语义聚类需要 embedding 或 NLI 模型；无外部依赖时，用近似 + 人工复核即可，但**要标明这是近似**。

## 3. 口头置信度的校准

模型自报的置信度**普遍过度自信**。RLHF 还会进一步磨掉预训练本就存在的不确定性信号（"对齐破坏信号"，ICML 2026）。

**不要直接采信，做三件事**：

1. **强制给理由**：要求同时输出"为什么是这个置信度"和"什么会推翻它"
2. **强制给反例**：低置信必须附"另一个合理答案是 X"（Cleanlab TLM 的做法）
3. **只用于路由，不用于免责**：置信度决定走哪档核查，不代表可以不核查

### 置信度 → 语言对齐表（忠实不确定性）

| 内部状态 | 语言必须降级为 |
|---|---|
| 高（有源 + 找过反证 + 多源一致） | "根据 X §2.1，……" |
| 中（有源但单一） | "目前只有 X 一个来源提到……，建议交叉核实" |
| 低（推断） | "据我所知倾向于……，但这一条我没把握，需要核实" |
| 无（无依据） | "这个我不确定" / "资料里没提" |

**最典型的幻觉不是内容错，是语气骗人。**

## 4. 为什么不做"低置信就拒答"

ICML 2026 的实用性税测算（基线错误率 25% → 目标 5%）：

| 判别力 AUROC | 需丢弃的正确回答 |
|---|---|
| 0.71 | 52% |
| 0.85 | 28% |
| 0.95（无方法接近） | 才可忽略 |

**拒答代价高到不可用。** 正确做法是四档路由：

```
高置信 + 高一致  → 直接答（带来源）
高置信 + 低一致  → 自相矛盾，触发定向检索
低置信 + 可检索  → 深度检索后重判
低置信 + 不可检索 → 说"不确定"+ 给反证方向 + L2 交给人
```

（路由思路与 PCC —— Probabilistic Certainty & Consistency —— 一致。）

## 5. 用 selfcheck.py

输入：多次采样的结果文件

```json
{
  "question": "该项目使用的 DI 框架是什么？",
  "samples": [
    "Hilt",
    "使用 Hilt 做依赖注入",
    "Dagger Hilt",
    "Koin"
  ]
}
```

```bash
PY=python3          # Windows 用 python
python3 scripts/selfcheck.py --samples samples.json
```

退出码是**路由信号**：0=高一致，2=灰区，**4=低一致**，3=用法/输入错误。
低一致用 4 而非 3，是为了不占用"错误"语义（与其他脚本保持一致）。

输出：

```json
{
  "question": "...",
  "n": 4,
  "clusters": 2,
  "consistency": 0.75,
  "dominant": "Hilt",
  "verdict": "gray_zone",
  "recommended_label": "assumed",
  "action": "升级：定向检索或子 agent 隔离验证"
}
```

**注意**：脚本做的是字面近似聚类。若输出落在灰区且成本高，人工过一眼比什么都准。

## 6. 三个必须记住的边界

1. **一致性高 ≠ 正确。** 模型可以稳定地重复同一个错误。一致性低是危险信号，一致性高只是及格线。
2. **温度不是治幻觉的手段。** 实证研究（npj Digital Medicine）显示温度对幻觉率影响很小；调温度只是为了采样多样性。
3. **置信度不是免责声明。** 标了"低置信"仍然输出错误信息，危害只是减轻，不是消失——所以还要附反证方向，让接收方能继续查。
