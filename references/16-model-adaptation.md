# 16 · 模型适配：不同强度的模型用不同打法

> 核心命题：**同一套核查策略不能套在所有模型上。**
> 关键差异不是"谁更聪明"，而是 **"谁能被信任做自我核查"**。

---

## 1. 分档的核心变量：trust_selfcheck

| 档 | 代表 | 自我核查可信? | 打法 |
|---|---|---|---|
| **S** | 前沿旗舰（Claude Opus 级、GPT-5 级） | ✅ | 模型内验证可用（CoVe 隔离验证、原生引用、自一致性）+ 外部硬核查兜底 |
| **A** | 主力模型（Sonnet 级、推理型 R1/o 系列级） | ✅（基本） | CoVe 可用；低置信才上多模型交叉；推理链不作为证据 |
| **B** | 轻量/中端（Haiku 级、4o-mini 级、7B~70B 开源） | ❌ | **不依赖自我核查**：全部走外部确定性脚本 + 强制引用 + 缩短单次输出 |
| **C** | 小模型/边缘（3.5 级、8B 以下） | ❌ | 只做**可判定项核查**（存在性），禁止开放式事实结论 |

**为什么弱模型的自我核查不可靠**：CoVe、自一致性这类方法的前提是"模型知道自己不知道"。
弱模型没有这个元认知——它无法区分自己答对还是答错，让它"再检查一遍"，
结果是**把错误答案再确认一遍**，还多了一层自信。

> 这对应 ICML 2026 的结论：判别力（AUROC 0.70–0.85）不足的代价是"拒答税"极高。
> 判别力更弱的模型，靠自我判断的代价只会更高。

**未知型号一律按 B 档**——宁可严，绝不放松。

## 2. 各厂商官方机制（一手来源，v3.4 已回溯核验）

完整摘录与斜体原文见 **`17-vendor-and-induction.md`**。这里是操作层要点：

| 厂商 | 官方机制（**一手出处**） | 怎么用它减少幻觉 |
|---|---|---|
| **Anthropic (Claude)** | 《Reduce hallucinations》官方文档（`platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations`）。三条基础策略 + 四条高级技巧；**原生 Citations API**（把每条声明锚定到源文档的 char/page/content-block 区间，返回 `cited_text`）；Extended Thinking；Tool Use | ① 明确给"说不知道"的**权限**（官方原句 + 示例指令在 17 章）；② 长文档 **>20k tokens 先逐字抽引文**再作答；③ 每条 claim 找支撑引文，**找不到就撤回并留 `[]`**；④ 有原生引用就别手写引用格式。官方自己声明：这些技术**显著减少但不能完全消除**幻觉 |
| **OpenAI (ChatGPT)** | *Why Language Models Hallucinate*（2025-09-05，arXiv 2509.04664）；Model Spec 的"谦逊"要求 | 核心是**评测激励**：主流 benchmark 只看 accuracy，会系统性地奖励猜测、惩罚弃权。SimpleQA 对照（gpt-5-thinking-mini 弃权 52%/错误 26% vs o4-mini 弃权 1%/错误 75%）是解释"为什么要有 unknown 标签"的最佳证据 |
| **Google (Gemini)** | Grounding with Google Search；函数声明 / 结构化输出 | 有 grounding 时优先用，别用参数记忆硬答 |
| **DeepSeek** | 推理型（R1 / reasoner）长思维链 | 思维链**不是证据**：长推理会引入中间步骤编造；中文语料强但中文二手来源密度高，更需回溯一手。另注意：框架依赖类谄媚（用户信念归因）在推理型上不一定更轻 |
| **开源小模型** | 通常无原生引用、无 logprobs、上下文短 | **自我反思是负资产**（见 §7 实证）：给它资料，别让它反思 |

> NIST 将 **confabulation** 定义为"自信呈现的错误或谬误内容"，
> 并明确警告**生成的引用本身可能是编造的**；建议组合使用原始证据核查 + 治理 + 内容溯源 +
> 部署前测试 + 事件披露。（NIST Generative AI Profile，一手来源）

## 3. 不同环境条件的适配

| 条件 | 影响 | 适配策略 |
|---|---|---|
| **无联网** | Zero Context 下外部事实无法核查 | 只能标 `unknown`，**禁止下事实结论**；把重心放在本地可判定项（文件/命令/账本） |
| **有联网** | 检索切片显著强于闭卷 | 优先检索，别用参数记忆（FACTS 榜单：Search 切片普遍高于 Parametric） |
| **短上下文** | 长文档塞不下，会静默丢信息 | 禁用"引用先行"（塞不进去）→ 改为**分片抽取 + 分片核查**；或直接换长上下文模型 |
| **推理型** | 长 CoT 引入中间编造（复杂任务上 CoT 可使幻觉 +12%） | 推理链只用于**生成验证问题**，不作为证据；结论仍需独立验证 |
| **无 logprobs** | 拿不到 token 概率做置信度 | 用采样一致性（`selfcheck.py`）或口头置信度 + 强制反例；别假装能拿到 |
| **多模态** | 视觉源幻觉是独立类别 | 不能套纯文本方案；图片里的实体要单独核查 |

## 4. 弱模型（B/C 档）的特别规则

这些是硬规则，不是建议：

1. **禁止在同一上下文里"再检查一遍。** 那不是核查，是重复确认。要验证就开独立子任务。
2. **单次产出的声明数压到 12（B）/ 5（C）条以内**，分批核查。一次问太多，弱模型会为了"答完"而编。
3. **无源即删执行得更严格**：拿不出来源就直接删，不给"推断"留口子（弱模型会把推断说成事实）。
4. **风险等级默认上调**：B/C 档 + 无联网 → 默认 L2（需人工闸门）。
5. **不让它做事实核查主体**：它可以做抽取、格式化、存在性判断；判断对错这件事交给外部脚本。
6. **输出结构要强制**：弱模型的指令遵循不稳定，用 JSON Schema / 模板字段约束输出。

## 4.5 弱模型为什么不能"反思"：一手实证（v3.4）

B 档往下"禁止再检查一遍"不再是经验之谈，有两条直接证据：

**证据一 · arXiv 2601.00513**（*When Small Models Are Right for Wrong Reasons*，AAAI 2026 TrustAgent Workshop）
3 个 7–9B 模型、10,734 条推理轨迹：

| 结论 | 数值 |
|---|---|
| 答案正确但**推理链本身有错**的比例 | **50%–69%** |
| RAG（给证据）对推理完整性的提升 | Cohen's d = **0.23–0.93**；计算类错误 −7.6% |
| self-critique / 元认知干预 | d = **−0.14 ~ −0.33**（**有害**） |
| 蒸馏出的轻量外部验证器 | F1 **0.86**，比 LLM judge 快 **100×** |

→ 弱模型的正确打法是：**给证据（RAG）+ 外部/蒸馏验证器**，而不是让它自我反思。

**证据二 · ICCSA 2026**（DOI 10.1007/978-3-032-30488-9_39）在 Llama-3.2-3B / Qwen3-4B 上实测 8 种方法：
没有任何单一方法在所有任务上占优；REPLUG 对 Qwen3-4B 最稳；ITI 与 Hermes 3 在 generative truthfulness 上 >30pp；
DoLa 稳定改善来源忠实度；**检索在某些配置上反而引入干扰项敏感性**。
→ 弱模型的方法必须**按自己任务实测选**，不能抄榜单。

## 5. 用 model_profile.py

```bash
python3 scripts/model_profile.py --list                      # 档位定义 + 厂商机制
python3 scripts/model_profile.py --model claude-opus-4 --net on
python3 scripts/model_profile.py --model gpt-4o-mini --net off --json
python3 scripts/model_profile.py --model deepseek-r1 --set    # 写入项目配置
python3 scripts/model_profile.py --show                       # 读当前配置
```

输出的是**可执行的策略**，不是描述：

```jsonc
{
  "tier": "C",
  "recommended": {
    "strategy": "只做可判定项核查：存在性检查为主，禁止开放式事实结论",
    "max_claims_per_pass": 5,
    "use_model_selfcheck": false,
    "require_external_evidence": true,
    "risk_level_default": "L2"
  }
}
```

**边界**：档位是**启发式默认值**，型号迭代极快，请以官方 model card 为准；
可用 `--override-tier S/A/B/C` 手动覆盖。联网能力属于运行环境，用 `--net on|off` 单独声明。

## 6. 与工作流其他环节的衔接

```
Q0 模型档位？（新增）  → model_profile.py → 决定核查策略与声明上限
Q1 上下文设定？        → Accurate / Noisy / Zero
Q2 风险等级？          → L0/L1/L2（弱模型自动上调）
Q3 有无可执行校验？    → 有 → hardcheck / dep_guard
```

| 档位 | CoVe 隔离验证 | 自一致性 | 外部硬核查 | 人工闸门 |
|---|---|---|---|---|
| S/A | ✅ 推荐 | ✅ 可用（但见天花板） | ✅ 必做 | L2 时 |
| B | ⚠️ 不可依赖 | ⚠️ 不可依赖 | ✅ **主力手段** | 建议常开 |
| C | ❌ 不用 | ❌ 不用 | ✅ **唯一手段** | 常开 |

一句话：**模型越强，越可以让模型帮忙核查；模型越弱，越要把判断权交给脚本。**

第二句（v3.4 新增，与强弱无关）：**用户希望答案是什么，永远不能进入证据链。**
谄媚是独立于模型能力的失败模式 —— 详见 `17-vendor-and-induction.md` §3。

## 8. 全档位共同的三条新禁忌（v3.4）

1. ❌ **禁止把用户的引导性前提带进验证子任务。** 核查前先做中性重述（模板见 17 章 §3）。
2. ❌ **禁止把"多次采样一致 / 多个 agent 一致"当确认。** 先查是否同源（共享则算 1 条），
   再记住天花板：FinQA 上 8/8 一致仍有 15–23% 错（arXiv 2607.11414；金融 QA 基准，
   三个 8–9B 模型上的结果，**是下界提示而非通用常数**）。
3. ❌ **禁止对小模型使用 self-critique / "反思一下"。** 实证有害（arXiv 2601.00513）。
   替代：给证据 + 外部验证器 + 压声明数 + 强制输出结构。
