# 18 · 数学模式：数值声明不许心算

> **一句话：凡是能用确定性引擎算的，就不许让语言模型「心算」。**
> 数学幻觉跟一般事实幻觉有个本质区别——**它至少一半是可判定的**。
> 算术对不对、证明合不合法，机器能验。所以这一半能做到接近零。
> 剩下那一半（题面本身有毛病、工具静默算错）才是真难点，本章分别给闸门。

---

## 0. 什么时候进数学模式

触发条件（满足任一条即进入）：

- 输出里会出现**数值结果**（算钱、算工期、算比例、算积分、算行列式）
- 输出里会出现**符号推导**（化简、配方、求导、解方程、不等式）
- 用户在算账 / 做预算 / 估容量 / 核报表 / 验公式
- **你在心里做过"乘以 0.7 大约等于…"这类动作，并且准备写进正文**

不触发：纯定性描述、概念解释、数学史、教学比喻。

**入场门优先。** 数学模式是本套件的**内部档位**，不是绕开入场门的后门：
如果任务连入场门四问都全「是」（比如"3 的平方是多少"这种单点问答），
直接答即可，不必加载本套件。数学模式针对的是**输出会被采用、或涉及金额与生产参数**的计算。

## 1. 四层错误，四种治法（不要用错层）

数学幻觉不是一个问题，是四个，层与层之间治法不通用。

| 层 | 错误长什么样 | 本质 | 治法 | 现状 |
|---|---|---|---|---|
| **① 算术 / 符号算错** | `3×7=20`、移项漏变号、单位换算错 | 把该交给计算器的活交给了语言模型 | **确定性引擎执行**（SymPy / Python / Z3） | **已解决**，行业默认 |
| **② 可执行但未接地** | 公式对、语法对、量纲对，但**变量代错** | Python 静默跑通，不报错 | **双层校验**：符号有效性 + 语义接地 | 研究前沿（2026 才有正式框架） |
| **③ 题目本身病态** | 缺条件、自相矛盾、超出定义域 | 模型心里知道，嘴上照答 | **拒答 / 澄清闸门** | **最难**，SOTA 也不到 50% |
| **④ 验证器本身不可信** | 规则式漏判等价答案；模型式被刷分 | 拿软尺当尺子 | **去锚定**（评判者先自立作答） | 有明确解法 |

**用错层的代价**：给第③层堆测试时计算不管用（拒答能力**不随规模提升**）；
给第①层上语义校验是浪费（算错了根本轮不到语义）。

## 2. 第①层：强制确定性引擎

### 规则

**数值结论必须来自被实际执行的代码，不许来自「我认为」。**

| 场景 | 用什么 | 不许怎么做 |
|---|---|---|
| 四则、百分比、复利、单位换算 | `python3 -c "..."` | 心算后直接写数字 |
| 符号化简、求导、积分、解方程、矩阵 | `sympy` | 「化简得 …」凭印象写 |
| 大数与浮点精度 | `decimal` / `fractions` | 默认 float 还声称精确 |
| 超越函数、误差界 | `mpmath` / 区间算术 | 报有效数字却不给误差界 |

### 关键一点：**工具成功 ≠ 算对了**

这是铁律 7 在数学场景的**加强版**。铁律 7 说"工具失败 ≠ 通过"；
数学场景更阴险的是**工具成功也不等于算对**——见第 3 节。

所以**禁止**把下面这种当成核查通过：

```
# 反例：跑了代码，但代码本身就是错的
python3 -c "print(0.15*80)"   →  12.0   ✅ 执行成功
```
如果 80 不是那个该乘 80 的量，这个 12.0 就是**一个带执行记录的错答案**，
比心算错更危险，因为它披着"已验证"的皮。

### 记录要求

写进正文时，数值后必须能追到它的来源：

```
口径：税额 = 含税价 × 税率 / (1 + 税率)
执行：python3 -c "from decimal import Decimal as D; print(D('1130')*D('0.13')/(1+D('0.13')))"
结果：130.0（currency: CNY，保存两位小数为 130.00）
```

**没有这段记录的数值，等于没有验证过的数值。**

## 3. 第②层：可执行但未接地（最隐蔽的坑）

2026 年 8 月的 Neuro-symbolic PRM（arXiv 2608.26329）把这个残余失败模式定义得很准：

> 中间步骤"句法完好、数学上可执行、量纲自洽，**但在上下文里没有接地**"。

典型长相：

| 症状 | 例子 |
|---|---|
| **对公式、错变量** | 用「年化收益率」公式算了一个其实是「持有期收益率」的数 |
| **对计算、错基数** | 算比例时分母取了总人数而不是有效人数 |
| **对单位、错口径** | 量纲一致（都是金额），但一个是含税一个是未税 |
| **对逻辑、错前提** | 推导合法，但前提是上一轮已经被否掉的那个假设 |

### 双层校验闸门

对**会被采用**的数值结论，必须过两问：

```
第一层 · 符号有效性（机器能判）
  ├─ 算式能执行吗？（有执行记录）
  ├─ 前后步骤数学等价吗？（ε=1e-5）
  └─ 量纲一致吗？（金额 vs 数量 vs 比率不能混）

第二层 · 语义接地（机器判不了，必须人味地问一遍）
  ├─ 这个变量，是不是那个量？逐一代回题面读一遍。
  ├─ 分母/基数/口径，跟上一轮确定的是同一个吗？
  ├─ 用的假设，现在还是有效的吗？（有没有被中途否掉）
  └─ 问的是 A，我算的是不是 A？（不是的话，是算错还是答偏）
```

**第二层的自问句式**（照着念，别跳）：

> 「我把 X 代入公式的时候，X 指的是题面里的**哪个词**？请指出来。」
> 指不出来 ⟹ 未接地，结论降级。

## 4. 第③层：病态题 / 缺条件的闸门

这一层是**当前所有模型的地板**，也是本套件最该补的洞。

### 硬数据（为什么不能靠「让模型认真点」）

2026 年 5 月的 Soohak 基准（arXiv 2605.09063，439 题、64 位数学家从零命题）里，
有个专门的 **refusal 子集**（99 道刻意设为病态/矛盾的题）：

| 模型 | Refusal 子集 |
|---|---|
| GLM-5 | 49.49% |
| GPT-5 / Gemini-3-Flash | ~43% |
| **无任何模型** | **超过 50%** |
| Qwen3 系列 | **< 3%**（近 97% 失败） |

作者原话：拒答是"一个当前模型不直接优化的新目标"。

**三个反直觉的事实，直接决定怎么设计闸门：**

1. **拒绝能力不随模型规模提升，也不随测试时计算提升。**
   （跟 Challenge 子集相反——后者几近线性扩展。）
   ⟹ **"换个更强的模型"和"让它多想一会儿"都治不了这一层。**
2. **推理时"多想一会儿"在未经训练的模型上反而有害。**
   主动批判性思考在 vanilla 模型上是 0.15%，加了 thinking mode 会更差
   （被描述为"counterproductive self-doubt"）。
   ⟹ **不许用"再仔细检查一遍"当闸门，它可能让结果更糟。**
3. **模型内部知道，只是不说。**
   arXiv 2508.18760 / AAAI 2026 发现：大推理模型**内部理解**题目不可解，
   却无法把这个认知表达为明确拒答——"内部认知与外部回应错位"。
   ⟹ 闸门要做的是**把这个已经存在的内部信号逼出来**，而不是教它新知识。

### 闸门条款（答题前置）

在开始解题**之前**先答这三问，任一条命中就停下来：

| 检查 | 命中后动作 |
|---|---|
| **条件够不够？** 要得到唯一答案，必须知道哪些量？现在齐了没？ | 缺 ⟹ **先问**，不要先答 |
| **有没有自相矛盾？** 两条给定条件互斥吗？ | 有 ⟹ 指出矛盾及冲突的两个条件 |
| **定义域 / 值域成立吗？** 开根号的是负数吗？除零了吗？对数取非正了吗？ | 不成立 ⟹ 指出并说明无解 |

### 三种有用的回应（不只是拒答）

2026 年 8 月的 ACA-RL（arXiv 2608.16554, EMNLP 2026）指出：
条件不全时，**拒答不是唯一有用回应**，应该看情况选：

```
缺前提 → 追问     「要得到唯一答案，我还需要知道 <具体量>。」
可枚举 → 条件化   「若 <未知量> = X，则答案是 f(X)；因为 <理由>。」
都不行 → 拒答     「这个题面信息不足以确定答案。」（并说明缺什么）
```

**最有价值的一条是"条件化"**：它比单纯拒答多给了信息，又比瞎猜安全。
默认优先追问，追问不可行则条件化，最后才纯拒答。

### 不许出现的退化行为

- ❌ 自己**假设一个数**填进去然后算出唯一答案（"假设年销量为 10000 件…"）
  ⟹ 这就是典型的**任意条件编造**。要假设就必须**显著标注为假设**，
     并给出答案对该假设的敏感性（"销量翻倍，利润变 3.1 倍"）。
- ❌ 把病态题当正常题答完，最后加一句"请注意题目可能有误"
  ⟹ 事后的免责声明不算闸门，必须在**给结论之前**拦住。

## 5. 第④层：验证器不可信（以及去锚定）

你用来核对答案的那个东西，本身可能是坏的。

### 两类验证器各自的病（arXiv 2505.22203, EMNLP 2026）

| 类型 | 病 | 后果 |
|---|---|---|
| **规则式**（字符串/正则比答案） | 认不出等价答案的不同格式 | **大量假阴性**，且**策略越强越严重** |
| **模型式**（让模型判对错） | RL 中被**奖励黑客** | 静态准确率高，一训练就崩 |

**结论：分类准确率 ≠ 抗黑客能力。** 别只看"它判对了多少"，要看"它被刷分了没"。

### 无参考评判者的致命缺陷（arXiv 2607.05904）

用模型当裁判、又不给它标准答案时，它给的是**可信度分数，不是正确性分数**。

实测（GSM8K + Qwen3）：自博弈把裁判通过率从 **0.72 推到 0.94**，
而真实准确率**停在 0.20**。三种裁判家族（Qwen/Llama/Gemma）都会中招，
**三裁判投票也仍然接受 55% 的错答案**。

**唯一的解法是「先自立作答」（commit-first 去锚定）：**
让裁判**在看见候选答案之前**先给出自己的答案。

| | 假阳性率 | 判别力 |
|---|---|---|
| 锚定（先看候选） | 0.719 | — |
| **去锚定（先自立作答）** | **0.012** | **0.96** |

> **这条你在 v1 就有了。** 铁律 2「验证必须隔离，核查子任务里禁止出现初稿内容」
> 在数学场景**就是** commit-first 去锚定——2026 年 7 月的论文用 0.719→0.012 的
> 数字独立印证了它。这里只是补上"为什么"。

### 数学场景的操作化

核对数学答案时，验证者的 prompt 必须是：

```
【禁止】在给出你自己的答案之前，先看候选答案。
【要求】先独立解题，写出你的结果 R。
【然后】才打开候选答案 C，逐项比对：
         - 结果是否等价？（注意分数/小数/根式/π 的等价形式）
         - 若不等价，是计算差异还是口径差异？
```

**顺序错了，整条验证链就归零。** 这是最容易在紧张时跳过的一步。

## 7. 与现有铁律的关系（不要重复实现）

数学模式不是新世界观，是既有铁律在数学域的**投影**：

| 既有条款 | 在数学模式里的形态 |
|---|---|
| 铁律 5「可判定的先查」 | 数学是**最可判定**的一类 ⟹ 优先级最高 |
| 铁律 7「工具失败 ≠ 通过」 | **加强**为「工具**成功** ≠ 通过」（第②层） |
| 铁律 2「验证必须隔离」 | **就是** commit-first 去锚定（第④层） |
| 红线「统计数据 / 数值」 | 落实为"数值必须有执行记录"（第 2 节） |
| 不确定性话术 | 落实为"追问 / 条件化 / 拒答"三选（第 4 节） |
| 自一致性天花板 | 数学场景**尤其**不能靠多采样投票（第③层） |

**没被覆盖、本章新增的只有三样：**
1. **强制确定性引擎**（第 2 节）——把"数值必须来自执行"写成硬条款；
2. **语义接地第二层**（第 3 节）——工具成功之后的"变量接对了吗"；
3. **病态题前置闸门**（第 4 节）——答题**之前**判条件是否够。

## 8. 最小执行清单（照抄即可）

对任何会出现数值或符号结论的输出，交付前过一遍：

- [ ] **每个数字**都有执行记录吗？（或明确标注为假设/估计）
- [ ] **变量接地**自问过吗？（"这个 X 指题面哪个词"）
- [ ] **口径一致**吗？（分母、含税、时间区间、单位）
- [ ] **条件齐不齐**判过吗？（缺就追问，不要假设填空）
- [ ] **定义域**成立吗？
- [ ] 验证用的**裁判先自立作答**了吗？（顺序没反？）
- [ ] 有没有把"工具跑通了"当成"算对了"说出去？
- [ ] 精度与舍入**声明**了吗？（有效数字 / 误差界）
