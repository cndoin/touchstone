# 07 · 大项目模式：让 AI 在超级庞大项目里不产生幻觉

> 这是 v2 新增的核心模块。前面所有机制解决的是"单次回答"的幻觉；
> 大项目的幻觉是**累积性**的——第 3 天的一句错话，到第 30 天会变成所有人默认的"既定事实"。

---

## 1. 大项目的五种特有幻觉

| 类型 | 表现 | 为什么会这样 |
|---|---|---|
| **记忆漂移** | "我记得 `utils/` 下有个 `Http.kt`"——其实早就被删了 | 上下文窗口装不下整个项目，模型用早期印象补全 |
| **状态幻觉** | "登录模块已经做完了"——其实只写了 UI | 完成标准未定义，模型把"写过代码"当成"做完" |
| **约定漂移** | 这次用 Hilt 注入，下次写成 Koin | 架构决策只存在于早期对话里，没落盘 |
| **回声幻觉** | 子 agent 说"已完成"，主 agent 直接采信，一层层放大 | 报告未经独立验证就被当作事实 |
| **跨会话遗忘** | 新会话重建上下文时，把推测当成上次定好的结论 | 没有账本，只能凭印象重建 |

**共同根因**：项目的真实状态在磁盘上，而模型的认知在上下文里；两者之间没有任何强制同步机制。

---

## 2. 六条大项目铁律

1. **先读后说。** 陈述代码库现状前，实际读文件或跑命令。禁止"我记得……"。
2. **账本即真相。** 架构决策、API 契约、命名约定写进 `ledger.json`；后续所有声明对照账本。
3. **账本不是免检证。** 账本会过期。定期 `ledger.py check --drift` 比对现实，冲突时**以现实为准**并更新账本。
4. **子 agent 的报告是声明，不是事实。** 独立验证后才可升级标签。
5. **完成标准先定义。** 每个任务开工前定义"什么算做完"（测试通过？编译通过？文件存在？）。
6. **里程碑闸门。** 每个里程碑跑一次全量核查（硬核查 + 账本漂移 + 回归集），不达标不许推进。

## 3. 决策账本（Decision / State Ledger）

### 记什么

| kind | 内容 | 例子 |
|---|---|---|
| `decision` | 架构决策与技术选型 | DI 框架 = Hilt；网络层 = OkHttp SSE |
| `contract` | 接口/数据契约 | `Message` 表字段、API 路径、DTO 结构 |
| `convention` | 命名与代码风格约定 | 包名前缀、ViewState 后缀 |
| `state` | 模块完成状态 | Chat 模块 = 已完成（测试用例 12 条通过） |
| `constraint` | 硬约束 | compileSdk 35，不允许升 AGP |
| `fact` | 值得长期记住的项目事实 | 本地无 Docker，编译必须走 CI |

### 怎么用

```bash
PY=python3          # Windows 用 python

# 记账
python3 scripts/ledger.py add --kind decision --subject "DI 框架" --value "Hilt" \
     --source "docs/arch.md#3" --file .touchstone/ledger.json

# 查询（大项目里回答"我们用的什么 X"之前必做）
python3 scripts/ledger.py get --subject "DI 框架"

# 漂移检测：账本 vs 真实现状
python3 scripts/ledger.py check --root . --drift
```

### 账本条目的验证字段

每条账本记录可挂一个 `verify` 描述，让 `check` 能自动比对：

```json
{
  "kind": "decision",
  "subject": "DI 框架",
  "value": "Hilt",
  "source": "docs/arch.md#3",
  "verify": {
    "type": "file_contains",
    "path": "app/build.gradle.kts",
    "pattern": "hilt"
  },
  "verified_at": "2026-09-16",
  "status": "confirmed"
}
```

`check` 会**实际读文件**验证 `verify` 条件；不满足 → 报 `drift`，该条自动降级为 `stale`，不允许再作为 `confirmed` 引用。

## 4. 上下文管理：读得少，就不要说得多

| 现象 | 对策 |
|---|---|
| 项目太大，读不全 | **划定本次任务的边界文件集**，只对边界内的内容下结论，边界外的明确说"未读" |
| 长文档 >20k tokens | **先逐字抽取引文**，再基于引文作答（Anthropic 官方做法），禁止"通读印象" |
| 读过的文件后来被改了 | 重新读。跨会话的观测视为过期（90 天规则的大项目变体：**跨会话即过期**） |
| 需要全局把握 | 用 `rg`/Grep 做结构化检索，而不是"我大概记得" |

### 引用先行的工作方式

```
1. grep/rg 定位相关片段
2. 把片段原文（含文件路径 + 行号）贴进上下文
3. 基于引文作答，每条结论挂 (文件路径#行号)
4. 引文里没有的 → 说"未找到"，不许补
```

## 5. 子 agent 的使用规范

子 agent 是大项目里幻觉传播最快的通道。**默认不信，验证后信。**

| 环节 | 规则 |
|---|---|
| 派发 | 给**最小必要背景**，不把自己的结论写进去（否则就是锚定） |
| 要求 | 明确要求输出：结论 + 证据原文 + 路径/命令输出；禁止只给结论 |
| 回收 | 对其结论执行 [8] 执行同闸：文件真存在？测试真过？命令真跑过？ |
| 标签 | 未验证前 = `hearsay`；独立验证后 = `observed`（单次）或 `confirmed`（≥2 独立源） |
| 冲突 | 多个子 agent 结论冲突 → 不一致本身就是信号，走 L2 升级 |

## 6. 检查点闸门（里程碑）

每个里程碑结束前跑一次：

```bash
# 1) 硬核查：所有对外输出的 URL/文件/命令/版本
python3 scripts/hardcheck.py --batch .touchstone/checks.json

# 2) 账本漂移
python3 scripts/ledger.py check --root . --drift

# 3) 回归集（含本次新增的出错案例）
python3 scripts/regression.py --cases assets/regression-cases.json

# 4) 输出契约闸门
python3 scripts/claim_lint.py --input .touchstone/claims.json --min-level L1
```

全绿才推进下一步。**任何一个脚本非零退出 = 闸门不放行。**

## 7. 完成标准的定义模板（防状态幻觉）

开工前写清楚，避免"写完代码"被当成"做完"：

```
任务：实现消息分支切换
完成标准（可机器验证）：
  ✅ app/src/.../BranchRepository.kt 存在
  ✅ ./gradlew :app:compileDebugKotlin 退出码 0（贴完整输出）
  ✅ 分支切换的单元测试 3 条通过（贴 pass 数）
  ✅ git diff 只包含预期文件
未完成即：任一 ❌ → 状态 = 未验证，不允许说"已完成"
```

## 8. 大项目自检清单（每次交付前）

- [ ] 关于代码库现状的每条陈述，本次会话都**实际读过**文件/跑过命令？
- [ ] 关于项目约定的陈述，对照了 `ledger.json`（而不是印象）？
- [ ] 账本跑过 `check --drift`，无 `stale` 条目被当作事实引用？
- [ ] 子 agent 的结论都独立验证过，没有直接采信？
- [ ] "已完成"的每一条都有可追溯的工具输出？
- [ ] 完成标准里的所有机器可验证项都实际跑过？
- [ ] 本次新增的出错案例已加入回归集？
