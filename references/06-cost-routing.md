# 06 · M6 检测器选型与成本路由（ADR）

> 来源：HalluScan（arXiv 2026）的 ADR（Adaptive Detection Routing）+ OpenFactCheck（arXiv 2405.05583）的可插拔架构
> 注意：HalluScan 的具体数值（NLI AUROC 0.88、成本降 2.0×、AUROC 降 0.1%）来自论文摘要转述，**属二手数据，引用前请回溯原文**。

**核心结论：没有通用最优检测器。** HalluScan 跑了 72 种配置（6 检测法 × 4 模型族 × 3 领域），OpenHalDet（arXiv 2606.06959）横向评了 17 数据集 × 16 检测器，结论一致——检测器效果强依赖场景。

但有个好消息：**可以用路由把成本砍一半而几乎不掉点**。

---

## 1. 选型决策树（成本优先）

```
有 reference 文本吗？（原文 / 检索到文档 / 已知权威材料）
├─ 有 → 【便宜】NLI 蕴含判断（DeBERTa-NLI / HHEM / Lynx）
│        HalluScan 数据：NLI Verification 是最优单一方法（AUROC 0.88）
│        成本：20–50ms/claim（GPU），可逐请求跑
│        本套件内的等价物：对照原文逐条判定 supported/contradicted
└─ 没有 → 需要外部证据吗？
    ├─ 可以检索 → 【中】FacTool 式：query generation → 工具查询 → 证据聚合
    │              本套件：hardcheck.py + 定向检索
    └─ 不能检索 → 【中】自一致性（多次采样）或不确定性打分
                   本套件：selfcheck.py（语义一致性统计）
```

**灰区才升级**：便宜手段分数落在灰区（置信度 0.3–0.85）→ 才上贵的手段（LLM-as-judge / 多模型交叉，贵 10–100×）。

---

## 2. 三档投入

| 档 | 手段 | 适用 | 成本 |
|---|---|---|---|
| **便宜（默认）** | 硬核查（URL/DOI/文件/命令/版本）、NLI 蕴含、多次采样一致性 | 全部声明先过这一档 | 近乎零 |
| **中** | 定向检索 + 多来源交叉 + 子 agent 隔离验证 | 便宜档落灰区的声明 | 1× |
| **贵（慎用）** | LLM-as-judge、多模型交叉、Best-of-N | L2 高风险 + 灰区仍未决 | 10–100× |

实测收益（ADR）：按这个路由，成本降 **2.0×**，AUROC 仅降 **0.1%**。

---

## 3. OpenFactCheck 的三插槽（可插拔设计）

三个组件可自由替换，本套件的对应实现：

| 插槽 | 开源实现 | 本套件 |
|---|---|---|
| **Claim Processor**（声明抽取） | FActScore / FacTool | Step 2 原子化（句子 + 三元组） |
| **Evidence Retriever**（证据检索） | 搜索引擎 / Wikipedia dump / 向量库 | 检索工具 + `hardcheck.py` + 本地文件读取 |
| **Verifier**（判定器） | NLI 模型 / LLM-judge / 规则 | 三档路由 + `claim_lint.py` |

**为什么重要**：三个插槽独立，才能适配"离线/在线/有库/没库"各种环境。离线环境把 Retriever 换成"只读本地文件"，整套流程照样跑。

## 4. 各检测器的适用边界（别用错）

| 方法 | 管什么 | 不管什么 |
|---|---|---|
| **NLI 蕴含** | 忠实性（输出 vs 给定原文） | 事实性（原文本身错了它查不出） |
| **硬核查** | 存在性（URL/DOI/文件/API/版本） | 语义正确性 |
| **自一致性 / 语义熵** | 模型内部是否稳定 | 是否真的对（全错但一致 = 高分） |
| **外部检索** | 事实性（有公开资料的问题） | 私有知识、无公开资料的问题 |
| **LLM-as-judge** | 复杂主张的近似判断 | 不能当最终裁决，它自己也会幻觉 |

> 关键提醒：**自一致性高 ≠ 正确**。模型可能稳定地重复同一个错误。语义熵/自一致性是"内部不确定性的代理指标"，不是正确性证明。

## 5. 路由表（可直接抄）

| 输入特征 | 走哪档 |
|---|---|
| 声明含 URL/DOI/文件/命令/版本/API | **便宜**：hardcheck.py 必跑 |
| 有权威原文可对照 | **便宜**：NLI/逐条对照 |
| 无原文、可检索 | **中**：定向检索 + 交叉 |
| 无原文、不可检索 | **中**：selfcheck.py 一致性 → 低一致必降级 |
| L2 风险 + 仍落灰区 | **贵**：多模型交叉 + 人工闸门 |
| 模糊主张（"这个方案更好"） | **不核查**，标为观点/推断，不走事实闸门 |

**最后一行很重要**：不要对模糊主张做无限核查。收敛到可判定的窄面，性价比高得多（微软 refchecker 的核心洞见）。

---

## 6. 成本上限（防止核查本身失控）

| 场景 | 建议上限 |
|---|---|
| L1 单条声明 | 便宜档为主，灰区最多上 1 次定向检索 |
| L1 整体 | 核查成本 ≈ 生成成本的 1–3 倍可接受 |
| L2 | 不限，但必须有人工闸门收口 |
| 大项目检查点 | 每个里程碑 1 次全量，不要每次对话都全量 |
